# LMPC Mobile — Field Officer App (Flutter)

Cross-platform (Android + iOS) companion app for the Legal Metrology Compliance
Checker, per `implementation.md` §1:

> Mobile client: **Flutter** (Android + iOS from one codebase) with local
> SQLite (**drift**) for offline queue — offline-first is non-negotiable.

## What's implemented (Dart source, complete)

| Area | File | Notes |
|---|---|---|
| App entry + DI | `lib/main.dart` | Provider-based wiring |
| Offline queue DB | `lib/src/db/app_database.dart` | drift tables: `pending_scans` (idempotent `capture_id`), `cached_verdicts`, `cached_cases` |
| Gateway API client | `lib/src/api/api_client.dart` | login, case list, multipart scan upload (idempotent), process, verdict fetch |
| Sync engine | `lib/src/services/sync_service.dart` | connectivity-triggered + periodic drain, exponential-bounded retry, permanent-4xx handling |
| Auth | `lib/src/services/auth_service.dart` | token in `flutter_secure_storage` |
| Login UI | `lib/src/screens/login_screen.dart` | |
| **GPay-style camera capture** | `lib/src/screens/capture_screen.dart` | live viewfinder, shutter, flip camera, gallery upload fallback, up to 4 shots, metadata form (package type, PDP area, scale reference), geo tag |
| Scan-frame overlay | `lib/src/widgets/scan_frame_overlay.dart` | corner brackets + animated scanline |
| Home / queue UI | `lib/src/screens/home_screen.dart` | live queue stream, per-scan sync status, verdict chips (PASS/FAIL/REVIEW), manual retry |

## Offline-first behaviour (design.md §4.1)

1. Every capture is written to local SQLite **first** with a client-generated
   `capture_id` (UUID) — the same idempotency key the web client uses.
2. `SyncService` drains the queue when connectivity returns; the server dedupes
   on `capture_id`, so a flaky-network retry can never double-process a scan.
3. Verdicts are cached locally for offline viewing.
4. Failed syncs surface in the queue UI with a manual retry button; permanent
   4xx errors stop retrying, transient errors back off (max 8 attempts).

## Building (on your machine — not buildable in the web sandbox)

Requires Flutter ≥ 3.19 with Android SDK and/or Xcode installed.

```bash
cd mobile/lmpc_mobile

# 1. Generate the platform folders (android/, ios/) around this Dart source
flutter create . --project-name lmpc_mobile --org gov.consumeraffairs.lmpc

# 2. Merge the permission snippets:
#    android/app-src-main-AndroidManifest-snippet.xml  -> android/app/src/main/AndroidManifest.xml
#    ios/Info-plist-snippet.xml                        -> ios/Runner/Info.plist

# 3. Install deps + generate drift database code
flutter pub get
dart run build_runner build --delete-conflicting-outputs

# 4. Point the app at your gateway (deployed URL or local dev server)
flutter run --dart-define=LMPC_API=https://your-deployment.pages.dev
# Android emulator against local sandbox dev server:
# flutter run --dart-define=LMPC_API=http://10.0.2.2:3000

# 5. Release builds
flutter build apk --release --dart-define=LMPC_API=https://your-deployment.pages.dev
flutter build ipa --release --dart-define=LMPC_API=https://your-deployment.pages.dev   # macOS + Xcode required
```

> **Note:** `app_database.g.dart` is generated by step 3 (`build_runner`) — it
> is intentionally not committed.

## API contract used

```
POST /api/v1/auth/login                          {username, password} -> {token, user}
GET  /api/v1/cases                               -> {cases: [...]}
POST /api/v1/cases/{case_id}/scans               multipart: capture_id, images[], metadata (idempotent)
POST /api/v1/scans/{scan_id}/process             -> {evaluation: {overall_status, verdicts}}
GET  /api/v1/scans/{scan_id}                     -> scan + extraction + evaluation
```

Same endpoints, same idempotency semantics as the web PWA — one gateway serves
both clients.
